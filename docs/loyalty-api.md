# API сервиса лояльности — документация для фронтенда

Бэкенд программы лояльности Coffee Exchange (Бины, купоны, QR, оплата). Документ описывает все публичные эндпоинты, нужные веб-фронтенду.

## Базовый URL

```
https://api-loyalty.coffeeexchange.ru/api/v1
```

- Все пути ниже указаны **относительно** этого префикса (`/auth/sms/request` = `https://api-loyalty.coffeeexchange.ru/api/v1/auth/sms/request`).
- Формат — JSON (`Content-Type: application/json`).
- Денежные суммы — строки с двумя знаками (`"378.00"`), валюта отдельным полем (`"RUB"`). Бины — целые числа.
- Даты — ISO 8601 UTC (`2026-06-12T15:48:04.797410Z`).
- Интерактивная схема (Swagger): `GET /docs`, OpenAPI: `GET /openapi.json`.

---

## Авторизация

Вход — по номеру телефона через SMS-код. После верификации выдаётся пара токенов:

- **access-токен** (JWT, живёт ~15 минут) — передаётся в каждом защищённом запросе:
  ```
  Authorization: Bearer <access_token>
  ```
- **refresh-токен** (живёт ~30 дней, ротируется при каждом обновлении) — хранится на клиенте, используется для получения новой пары, когда access протух.

Рекомендация по хранению: токены держать в памяти/secure-storage; при `401` на защищённом запросе — попытаться `POST /auth/refresh`, при неудаче — отправить на повторный вход.

Эндпоинты `auth/*`, `menu`, `countries`, `rules` — **публичные** (без токена). Всё остальное (`users`, `loyalty`, `coupons`, покупки) требует `Authorization: Bearer`.

## 1. Аутентификация

### POST /auth/sms/request — запросить SMS-код
Тело:
```json
{ "phone": "+79161234567" }
```
Ответ `200`:
```json
{ "detail": "Код отправлен" }
```
Ошибки: `422` некорректный номер; `429` слишком частые запросы (есть кулдаун); `502` провайдер SMS недоступен.

### POST /auth/sms/verify — подтвердить код и войти
Тело:
```json
{ "phone": "+79161234567", "code": "123456" }
```
Ответ `200`:
```json
{
  "access_token": "eyJ...",
  "refresh_token": "a1b2c3...",
  "token_type": "bearer",
  "is_new": true
}
```
- `is_new` — `true`, если пользователь зарегистрирован этим входом впервые (можно вести на экран заполнения профиля).
Ошибки: `400` неверный или просроченный код; `403` пользователь заблокирован.

### POST /auth/refresh — обновить пару токенов
Тело:
```json
{ "refresh_token": "a1b2c3..." }
```
Ответ `200` — новая пара токенов (`is_new: false`). Старый refresh становится недействительным (ротация).
Ошибки: `401` недействительный refresh — нужен повторный вход.

### POST /auth/logout — выйти
Тело:
```json
{ "refresh_token": "a1b2c3..." }
```
Ответ `200`: `{ "detail": "Сессия завершена" }`. Отзывает refresh-токен.

## 2. Профиль пользователя 🔒

### GET /users/me — текущий профиль
Ответ `200`:
```json
{
  "id": "2ade4444-...",
  "phone": "+79161234567",
  "code": "02245803",
  "first_name": "Егор",
  "last_name": "Фролов",
  "middle_name": null,
  "birth_date": "2005-08-05",
  "email": "egor@example.com",
  "country_code": "RU",
  "consent_version": "1.0",
  "profile_completed": true
}
```
- `code` — 8-значный персональный код пользователя (для штрихкода на кассе).
- `profile_completed` — `true`, когда заполнены **`first_name`**, **`birth_date`** и **`consent_version`**. Используйте как признак завершённой регистрации.

### PATCH /users/me — обновить профиль
Тело (все поля опциональны, обновляются только переданные):
```json
{
  "first_name": "Егор",
  "last_name": "Фролов",
  "middle_name": null,
  "birth_date": "2005-08-05",
  "email": "egor@example.com",
  "country_code": "RU",
  "consent_version": "1.0"
}
```
Ответ `200` — обновлённый профиль (как в `GET /users/me`).
- Передача непустого `consent_version` фиксирует согласие (момент согласия проставляется сервером).
- Чтобы завершить регистрацию (`profile_completed: true`), пришлите имя + дату рождения + версию согласия.
Ошибки: `422` некорректная страна/поля.

### GET /users/me/barcode — данные штрихкода
Ответ `200`:
```json
{ "code": "02245803", "format": "code128" }
```
- `code` — то же, что в профиле; `format` — формат для рендера штрихкода на клиенте. Это код, который кассир сканирует для идентификации гостя.

## 3. Справочники (публичные)

### GET /countries — список активных стран
Ответ `200`:
```json
[ { "code": "RU", "name": "Россия", "currency": "RUB", "is_active": true } ]
```

### GET /rules?country=RU — правила программы
Query: `country` (обязательно, код страны).
Ответ `200`:
```json
{ "country_code": "RU", "version": 3, "text": "Текст правил...", "created_at": "2026-06-01T..." }
```
Ошибки: `404` правила для страны не опубликованы.

## 4. Меню (публичное)

### GET /menu?country=RU — меню страны
Query: `country` (обязательно).
Ответ `200` — массив позиций:
```json
[
  {
    "id": "8e9df69a-...",
    "pos_item_id": "c87e2046-...",
    "size_id": "757067fe-...",
    "name": "Капучино",
    "size_name": "0.2",
    "category": "Кофе",
    "currency": "RUB",
    "base_price": "330.00",
    "dynamic_price": "331.00",
    "price_beans": 100
  }
]
```
- `base_price` — базовая цена; `dynamic_price` — текущая цена с динамическим ценообразованием (показывайте её). Если Pricing недоступен — `dynamic_price` равен базовой.
- `price_beans` — стоимость в Бинах (или `null`, если за Бины не продаётся).
Ошибки: `404` страна не найдена.

### GET /menu/items/{item_id} — карточка напитка
Ответ `200` — позиция (как выше) + модификаторы:
```json
{
  "id": "8e9df69a-...",
  "name": "Капучино",
  "...": "...",
  "modifiers": [
    { "id": "...", "pos_modifier_id": "M1", "name": "Сироп", "base_price": "50.00", "price_beans": null }
  ]
}
```
Ошибки: `404` напиток не найден.

## 5. Бины (бонусный баланс) 🔒

### GET /loyalty/balance — баланс
Ответ `200`: `{ "balance": 350 }`

### GET /loyalty/transactions — история операций
Query (все опциональны):
- `type` — фильтр по типу: `accrual` (начисление), `spend` (списание), `expire` (сгорание);
- `from`, `to` — диапазон дат (ISO 8601), например `from=2026-01-01T00:00:00Z`;
- `limit` (1–100, по умолчанию 20), `offset` (по умолчанию 0).

Ответ `200`:
```json
{
  "items": [
    { "id": "...", "type": "accrual", "amount": 3, "comment": null, "correlation_id": "receipt-1", "created_at": "2026-06-10T..." }
  ],
  "total": 12,
  "limit": 20,
  "offset": 0
}
```
- `amount` положительный для начислений, отрицательный для списаний/сгораний.

> Начисление Бинов происходит на кассе при оплате (≈1 Бин за каждые 100 ₽ чека). Бины живут 365 дней. Фронт лишь отображает баланс и историю.

## 6. Купоны 🔒

Купон — это право получить напиток на кассе по QR. Покупается за Бины или за деньги.

### Модель купона
```json
{
  "id": "...",
  "status": "active",
  "qr_token": "BASE32TOKEN",
  "purchase_kind": "bean",
  "price_beans": 100,
  "price_money": null,
  "currency": "RUB",
  "country_code": "RU",
  "expires_at": "2026-09-10T...",
  "reserved_at": null,
  "used_at": null,
  "created_at": "2026-06-12T...",
  "snapshot_items": [
    { "kind": "drink", "pos_id": "c87e2046-...", "name": "Капучино", "size_name": "0.2", "price_money": "331.00", "price_beans": 100 }
  ]
}
```
- `status`: `active` (можно использовать), `reserved` (предъявлен на кассе, идёт оплата), `used` (погашен), `expired` (просрочен).
- `purchase_kind`: `bean` (куплен за Бины) или `money` (за деньги).
- `qr_token` — содержимое QR-кода, который показывают на кассе.
- `snapshot_items` — что входит в купон, зафиксировано на момент покупки. Поле `kind`: `drink` — напиток, `modifier` — модификатор. То же `kind` у строк `items` в котировках.

### GET /coupons — мои купоны
Query: `status` (опц., фильтр), `limit` (1–100, def 20), `offset` (def 0).
Ответ `200`:
```json
{ "items": [ /* CouponOut */ ], "total": 5, "limit": 20, "offset": 0 }
```

### GET /coupons/{coupon_id} — детали купона
Ответ `200` — `CouponOut`. Ошибки: `404` не найден.

## 7. Покупка купона за Бины 🔒

Двухшаговый флоу: **котировка → покупка**. Котировка фиксирует цену/стоимость в Бинах на **60 секунд** и **одноразова**.

### Шаг 1. POST /coupons/quote-bean
Тело:
```json
{ "item_id": "8e9df69a-...", "modifier_ids": ["M1-uuid"] }
```
(`modifier_ids` — опционально, список id модификаторов.)
Ответ `200`:
```json
{
  "quote_id": "q_abc123",
  "total_beans": 100,
  "total_money": "331.00",
  "currency": "RUB",
  "expires_in": 60,
  "items": [ { "kind": "drink", "pos_id": "...", "name": "Капучино", "size_name": "0.2", "price_money": "331.00", "price_beans": 100 } ]
}
```
Ошибки: `404` напиток не найден; `409` напиток недоступен за Бины; `422` недопустимый модификатор.

### Шаг 2. POST /coupons — купить по котировке
Тело:
```json
{ "quote_id": "q_abc123" }
```
Ответ `200` — созданный `CouponOut` (`status: active`).
Ошибки: `409` котировка не найдена или истекла (>60 сек либо уже использована); `409` недостаточно Бинов.

> ⚠️ Запрашивайте котировку **непосредственно перед** покупкой и сразу отправляйте `POST /coupons` — между шагами не должно проходить >60 сек.

## 8. Покупка купона за деньги (ЮKassa) 🔒

Флоу: **котировка → создание платежа → оплата на странице ЮKassa → купон выдаётся по факту оплаты**.

### Шаг 1. POST /coupons/quote-money
Тело: `{ "item_id": "...", "modifier_ids": [] }`
Ответ `200`:
```json
{ "quote_id": "q_money1", "total_money": "331.00", "currency": "RUB", "expires_in": 60, "items": [ ... ] }
```
Ошибки: `422` недопустимый модификатор; `404` напиток не найден.

### Шаг 2. POST /coupons/purchase-money — создать платёж
Тело: `{ "quote_id": "q_money1" }`
Ответ `200`:
```json
{
  "payment_id": "uuid",
  "status": "pending",
  "confirmation_url": "https://yoomoney.ru/checkout/payments/...",
  "confirmation_token": null
}
```
Ошибки: `409` котировка истекла; `502` платёжный провайдер недоступен.

### Шаг 3. Оплата
- Перенаправьте пользователя на `confirmation_url` (страница ЮKassa — карта/СБП/ЮMoney).
- После оплаты ЮKassa вернёт пользователя на `return_url` (страница результата на фронте, напр. `/payment/result`).

### Шаг 4. Получение купона
Купон выдаётся **асинхронно** — по webhook от ЮKassa после подтверждения оплаты (не мгновенно в ответе шага 2). На странице результата:
- опрашивайте `GET /coupons` (или `GET /coupons/{coupon_id}`) с небольшим интервалом, пока не появится новый купон со `status: active` и `purchase_kind: "money"`;
- либо покажите «платёж обрабатывается» и обновите список купонов через несколько секунд.

> Отдельного эндпоинта статуса платежа для фронта нет — ориентируйтесь на появление купона в `GET /coupons`.

## Коды ошибок (общие)

Все ошибки — JSON вида `{ "detail": "текст" }`.

| Код | Значение |
|-----|----------|
| `400` | Неверные данные (например, просроченный SMS-код) |
| `401` | Нет/недействительный access-токен → обновить через `/auth/refresh` или войти заново |
| `403` | Пользователь заблокирован |
| `404` | Объект не найден |
| `409` | Конфликт: котировка истекла, недостаточно Бинов, купон недоступен |
| `422` | Ошибка валидации входных данных |
| `429` | Превышен лимит запросов (SMS, котировки и т.п.) — повторить позже |
| `502` | Внешний сервис недоступен (SMS-провайдер / платёжный провайдер) |

## Типовые сценарии

**Регистрация/вход:**
`POST /auth/sms/request` → `POST /auth/sms/verify` → сохранить токены. Если `is_new: true` или `profile_completed: false` → экран заполнения профиля (`PATCH /users/me` с именем, датой рождения, `consent_version`).

**Главный экран:** `GET /loyalty/balance` + `GET /menu?country=RU`. Карта лояльности — `GET /users/me/barcode` (рендер штрихкода по `code`).

**Покупка за Бины:** карточка `GET /menu/items/{id}` → при нажатии «Купить» `POST /coupons/quote-bean` → сразу `POST /coupons` → показать купон с QR (`qr_token`).

**Покупка за деньги:** `POST /coupons/quote-money` → `POST /coupons/purchase-money` → редирект на `confirmation_url` → возврат на страницу результата → опрос `GET /coupons` до появления купона.

**Купоны пользователя:** `GET /coupons` (список), `GET /coupons/{id}` (QR для предъявления на кассе).

## Примечания

- **CORS** настроен на домен фронта; при запуске с нового origin сообщите бэкенду для добавления в список разрешённых.
- **Динамические цены** меняются — для актуальной цены покупки всегда используйте котировку (`quote-*`), а не цену из меню.
- Все защищённые (🔒) эндпоинты требуют заголовок `Authorization: Bearer <access_token>`.
